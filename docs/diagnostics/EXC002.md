# EXC002: Exception is outside the declared contract

An explicit exception escapes a method whose `[Throws]` contract does not
include its type or a base type. Add a compatible declared exception, handle
the exception, or correct the contract. The message names the
namespace-qualified exception type. An annotated call that is outside the
caller contract is EXC003, not EXC002.

The reported type is the static type of the thrown expression before C#'s
implicit conversion to `System.Exception`. For example, throwing
`new MyException("failed", new Exception())` reports `MyException`; the inner
exception argument does not change the type being thrown. A derived exception
is covered by a declared base exception.

For `throw;`, the analyzer uses the enclosing catch type. A bare `catch`
therefore reports `System.Exception`, since the original runtime type cannot
be established from that handler. A catch-all that handles the original throw
prevents it from escaping, but a rethrow from the catch handler is checked as
an escaping exception.

When a source method implements one or more annotated interface members, its
escaping exceptions are checked against every implemented interface contract.
An exception must be permitted by all of them.

A constructor that lets `ArgumentNullException` escape is treated as if it
declared that exception. Another exception that escapes the same constructor
is EXC002. A nullable-redundant `ArgumentNullException` is EXC007 instead, and
is not also EXC002.

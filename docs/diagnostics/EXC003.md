# EXC003: Annotated call may throw an unhandled exception

A call, constructor invocation, property or event access, user-defined
operator, or user-defined conversion has a known `[Throws]` contract that is
not covered by a catch or the caller's `[Throws]` contract. Declare a
compatible exception or handle it.

A member with a reachable uncaught throw has that `[Throws]` contract even
when the source has no attribute. The caller must catch it or declare it.
The caller's own caller does not inherit the contract. An explicit `[Throws]`
or `[DoesNotThrow]` replaces the inferred set, so callers see only the
explicit contract. A constructor that only chains with `: this()` or
`: base()` is checked at that chain. EXC007 suppresses the inferred contract
for a nullable-redundant constructor guard.

The same check includes field and property initializers, `this()` and
`base()` constructor calls, synchronous `foreach` pattern methods
(`GetEnumerator`, `MoveNext`, `Current`, and `Dispose`), synchronous `using`
`Dispose`, and deconstruction assignments. `base` access is bound to the
selected member. A property or event `[Throws]` contract applies to its
accessors unless an accessor declares its own contract. `nameof` is not a
call. `GetEnumerator` is checked even though its return type is otherwise
treated as deferred, because `foreach` invokes it immediately.

An annotated interface member's contract is honored when the call is
statically made through an interface-typed value. Each interface call uses
that interface member's contract. A derived interface member that redeclares
a base member and does not declare its own contract keeps the base contract.
Several inherited contracts intersect, and an empty intersection is
`[DoesNotThrow]`. The message names each exception with its namespace.
Inside a source implementation, calls and throws use the intersection of
that method's contract and every interface contract it implements. A source
implementation that does not declare the same contract as the interface
member is also EXC009. A class-level `[Throws]` also applies to accessors,
including auto-property getters and setters. Diagnostic text names those
accessors as getters, setters, or event add and remove accessors, and names
constructors as constructors.

Open virtual and unsealed override calls are checked only for the explicit
`[Throws]` set on the statically selected method. An inferred throw, and
`[DoesNotThrow]`, on that method are not enforced at the call, because an
override can replace them. Abstract methods are checked when they declare
`[Throws]` and the return is not deferred. `base` calls are analyzed as the
selected member. Sealed methods and methods on sealed types are analyzed as
the selected method.

A direct call of a local function uses that local function's contract. A
throw inside the local function is not a throw of the enclosing method.
Invoking a lambda or method group stored in one delegate assignment reports
the callback's known exceptions. A delegate parameter annotated
`[DoesNotThrow]` or `[Throws]` uses that parameter contract when the method
invokes it.

Async and iterator bodies are skipped: `[Throws]` does not yet describe
exceptions observed when awaiting a `Task` or enumerating an iterator. C#
stores exceptions from an `async` method in its returned task even when the
throw occurs before its first `await`; exceptions after an `await` are
observed when the caller awaits that task. Iterator exceptions occur during
enumeration, including a throw before the first `yield`, and async iterator
exceptions during asynchronous enumeration. The analyzer skips those method
bodies, so it does not report those deferred failures as synchronous throws.

A call that returns `Task`, `ValueTask`, `IEnumerable`, `IEnumerator`,
`IAsyncEnumerable`, or `IAsyncEnumerator` is synchronous when the selected
method has an executable body and is not async or an iterator. A signature
with no body stays deferred, even when it declares `[Throws]`. Interface and
abstract members are in that group. An open virtual method with one of those
return types is also skipped. Deferred `await` and enumeration contracts
remain a separate future feature.

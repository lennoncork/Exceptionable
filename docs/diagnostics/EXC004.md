# EXC004: Invalid exception name in `[Throws]`

`[Throws]` must identify exactly one exception type. Use either form:

- `[Throws<System.IO.IOException>]`, where the type argument derives from
  `System.Exception`. The package attribute enforces that constraint. A
  source-defined generic attribute is checked the same way.
- `[Throws("System.IO.IOException")]`, a fully qualified metadata name. A
  leading `global::` is accepted and ignored. Nested types accept the metadata
  form (`N.Outer+NestedException`) or the dotted C# form
  (`N.Outer.NestedException`). A short name resolves when exactly one exception
  type has that name; another type with the same name that does not derive
  from `System.Exception` is ignored.

When more than one exception type matches, EXC004 says the name is ambiguous.
When the name or type argument identifies a type that does not derive from
`System.Exception`, EXC004 says so. Names that match nothing are invalid.

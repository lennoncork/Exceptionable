# EXC005: Conflicting exception contracts

The same class, struct, method, property, event, or parameter cannot have both
`[DoesNotThrow]` and `[Throws]`. `[Throws<TException>]` is a `[Throws]`
contract. Choose one contract. A method or accessor contract may still
override a separate property, event, or containing-type contract. Those are
different targets and are not EXC005. An interface type cannot carry either
attribute; annotate its members instead. A parameter contract is separate
from the method contract.

# EXC007: ArgumentNullException guard may be redundant

A constructor throws `ArgumentNullException` for a non-nullable reference
parameter while nullable annotations are enabled. The guard may be redundant
with the declared nullable contract, but nullable annotations are compile-time
contracts, not runtime checks. Keep the guard when the public API promises
runtime validation for nullable-oblivious callers, reflection, or other
languages.

The same warning applies when the throw does not name a parameter and every
reference-type parameter of the constructor is a non-nullable reference.
`string?` and `[AllowNull]` parameters are not covered: the caller is allowed
to pass null, so the constructor publishes an inferred
`[Throws(typeof(ArgumentNullException))]` contract and callers are checked
with EXC003. Other escaping throws on the same constructor are still inferred.
For a guard reported by EXC007, the analyzer does not publish that exception
as an inferred contract. Consequently, a nullable-oblivious caller does not
receive EXC003 for that guard, even though the guard can still throw at
runtime. An explicit `[Throws]` or `[DoesNotThrow]` replaces inference;
EXC007 remains an advisory warning.

The warning is enabled by default and has warning severity, but it does not
recommend removing a runtime validation boundary. Suppress EXC007 where the
guard is intentional. The warning is not also EXC002. A `[DoesNotThrow]`
constructor still reports EXC001 for the escaping throw.

`ArgumentNullException.ThrowIfNull` is an ordinary method call. It does not
produce EXC007 and does not create an inferred contract.

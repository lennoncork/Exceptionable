# EXC009: Implementation exception contract does not match interface

A source method, accessor, property, or event implements an interface member
that declares `[Throws]` or `[DoesNotThrow]`, but the implementation does not
declare an equivalent contract. Add the same attribution to the implementing
member, its property or event, or the containing class or struct.

Equivalence is the same `[DoesNotThrow]` or the same set of exception types.
`[Throws("IOException")]` and `[Throws<IOException>]` match when they resolve
to the same type. A derived exception type is not the same published
contract as its base type. An inferred throw from the method body is not a
match.

This is the Exceptionable analog of nullable's interface-implementation
mismatch warnings, including CS8770 for a missing `[DoesNotReturn]`. Throw
and call diagnostics still use the intersection of the implementation and
every interface contract. EXC009 does not replace EXC001, EXC002, or EXC003.

An unannotated interface member does not require the implementation to omit
attributes. Class virtual and override contract replacement is not EXC009.
When one method implements several interface members, each mismatched member
is reported. Explicit implementations can match each interface separately.
External implementations and methods inherited from a base class that does
not itself implement the interface are not reported.
